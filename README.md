## Самый быстрый запуск

1. Откройте <https://colab.research.google.com/>.
2. **Файл → Загрузить блокнот → Загрузить**: выберите `autoservice_colab.ipynb`.
3. **Среда выполнения → Сменить среду выполнения → T4 GPU → Сохранить**.
   Интерфейс может называться Runtime → Change runtime type → T4 GPU.
4. **Среда выполнения → Выполнить всё** (Runtime → Run all).
5. Не закрывайте вкладку. Первый запуск скачивает модели; это не зависание.
   Если появляется индикатор прогресса, процесс работает. Время зависит от доступности T4 и скорости сети;
   рабочий ориентир — 40–90 минут после выделения GPU, без гарантии.
6. Последняя ячейка скачивает `autoservice_results.zip`. Сохраните и сам выполненный notebook:
   **Файл → Скачать → Скачать IPYNB**. Ноутбук с выводами — дополнительный лог.
7. В архиве находятся код, данные, `REPORT.md`, графики, метрики, сырые ответы и
   `outputs/adapter/adapter_model.safetensors`. Отчёт зависит от реальных результатов.

Токен Hugging Face и платный API не требуются: модели публичные. Судья тоже работает на T4,
последовательно после студента. Подключение Google Drive не требуется.

## Что происходит

| Этап | Результат |
|---|---|
| 1. Установка, проверка CUDA, данных и автоматической проверки | `data/`, `outputs/check_examples.json`, логи |
| 2. Бейзлайн на 24 вопросах | `outputs/before.jsonl` (первые 2 ответа печатаются) |
| 3. 50 шагов QLoRA, answer-only loss, отдельный dev | `outputs/adapter/`, `train_summary.json`, loss logs |
| 4. Новая загрузка сохранённого адаптера и тот же тест | `outputs/after.jsonl` |
| 5. Qwen2.5-7B судит 6 пар в обеих позициях | `outputs/judge.jsonl` с сырым текстом и JSON |
| 6. Агрегация и отчёт | CSV/JSON, PNG, `REPORT.md`, ZIP |

Train — 100 записей / 20 семейств, dev — 8 / 4, test — 24 / 12.
Корпус синтетический, варианты train отличаются только вводной фразой; независимой
экспертной проверки нет. Проверяем в первую очередь перенос формата, а не новые технические знания.

## Запуск скриптами на Linux + NVIDIA GPU

Перейдите в эту папку. Нужны Python 3.10–3.12 и установленный PyTorch с CUDA.

```bash
python -m pip install -r requirements-colab.txt
python build_data.py
python checks.py
python experiment.py before
python experiment.py train
python experiment.py after
python experiment.py judge
python summarize.py
```

Для CPU-проверок достаточно стандартной библиотеки:

```bash
python build_data.py
python checks.py
```

Обучение и bnb-квантизация рассчитаны на Linux/CUDA, а не на локальный Mac.
Первый GPU-этап записывает SHA ревизий HF; повторные используют те же ревизии.
Сохраняйте `outputs/model_revisions.json` для точного воспроизведения.
Сравнение строго парное: те же вопросы, system prompt, квантизация и greedy decoding.
Значения bootstrap относятся к 12 семействам, не к 24 независимым обращениям.

## Если произошла ошибка

- **GPU не найден:** выберите T4. Если квота недоступна, без GPU этот эксперимент не продолжится;
  нужен другой доступный GPU-сеанс. Платная подписка не оформляется автоматически.
- **Ошибка pip / import:** пришлите последние 20–30 строк. Каждый GPU-этап работает в новом
  процессе; установка не требует перезапуска уже импортированного Transformers.
- **Out of memory:** перезапустите сеанс и повторите; batch уже 1. Если проблема воспроизводится,
  сохраните ошибку. Изменение `max_length`, модели или decoding нужно фиксировать и применять
  последовательно: для сравнения пересчитать обе версии, не только after.
- **Скачивание HF не идёт:** проверьте доступность Hugging Face в Colab; не вставляйте токены в чат.
- **Судья вернул не JSON:** текст сохранён, ошибочные строки исключаются с явным счётчиком.
  Если обе перестановки не получены, пара не входит в средние. Нельзя вписывать оценки вручную
  вместо неудачного вызова. При необходимости можно закончить с автоматической оценкой,
  честно описав попытку судьи; по заданию автоматической метрики достаточно для сравнения.
- **Сеанс разорвался после обучения:** если файлы в `/content/autoservice_sft` сохранились,
  запускайте с незавершённой ячейки; не распаковывайте весь проект заново. В notebook есть отдельная
  ячейка аварийного скачивания текущих результатов.
- **Повтор обучения:** создаёт новый адаптер и перезаписывает train-логи. После него заново
  выполните after, judge и сводку. Старые оценки нельзя использовать с новыми весами.

## Пересборка итогового отчёта

`python summarize.py` создаёт автоматическую сводку и перезаписывает `REPORT.md`.
Для восстановления итогового разбора именно опубликованного первого опыта:

```bash
python -m pip install -r requirements-report.txt
python build_final_report.py
```

Нужны шрифты DejaVu (в Colab/Linux: `/usr/share/fonts/truetype/dejavu`);
на другом компьютере передайте `--fonts /папка/с/DejaVuSans.ttf`.
Итоговый разбор закреплён за первым запуском и не применяется автоматически к
новым результатам: при изменении опыта используйте автоматическую сводку и
подготовьте новый анализ. Повторное обучение может иметь небольшие численные
расхождения на других версиях PyTorch/CUDA; исходное окружение сохранено.
